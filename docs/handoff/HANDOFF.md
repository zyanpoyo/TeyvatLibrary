# テイワット文庫（原神 聖遺物・武器・書籍リーダー）— 次期AI引き継ぎ設計書 (HANDOFF)

本ドキュメントは、プロトタイプ（`index.html`）で検証・確定した仕様とデータ構造を引き継ぎ、本番Webアプリケーションへ拡張するための設計・実装指示書である。

---

## 1. プロトタイプで確定したプロダクト定義とUX原則

### 解決する課題
原神の武器・聖遺物・書籍・突破素材のフレーバーテキストは作り込まれているが、以下の3つの理由でライトユーザーが気軽に読めない。
1. **固有名詞の秘匿**: 「少女」「彼」「一人目の愚者」のように代名詞や二つ名で書かれ、誰の話か分からない。
2. **テキストの断片化**: 聖遺物は5部位に分割され（しかもゲーム内順序と時系列が一致しない）、対になる物語が別武器やボス素材に分散している。
3. **入り口の不親切さ**: ゲーム内図鑑は「アイテム種別」で並ぶため、どのアイテムにどんな面白い物語があるか判断できない。

### プロトタイプで検証済みのコアUX・ビジュアル仕様（本番でも必ず維持すること）
- **原神「図鑑（Archive）」モチーフの星空・天球デザイン**:
  - 常時ダーク（星空）テーマに統一。背景には深い群青〜紫の星雲（Nebula）と、放射状に広がる天球の経線・瞬く星々を配置する。
  - **書架（一覧画面）上部ステージ**: 黄金の天文盤（アストロラーベ）と開いた魔導書から光が立ち昇り、ホログラム風の線画カテゴリーアイコン（星間書架／聖遺物誌／武器銘文／秘境伝承）が弧を描いて浮かび上がる。選択中のアイコンは白金〜紫蒼のグローで発光する。
  - **星図ガラスカード**: 物語カードは半透明ダークガラス（`backdrop-filter: blur`）に金枠と四隅の星紋（`✦`）をあしらう。
  - **読書画面（本文）でのコントラスト制御**: 読書ビューに入ると（`body[data-view="reader"]`）、背景の星雲・経線の輝度を一段落として視覚ノイズを抑え、高コントラストなダークガラス誌面上で文字をくっきり読ませる。
- **書架（一覧画面）の情報設計**: アイテム名ではなく **「1行キャッチコピー ＋ 読了目安時間 ＋ 関連キャラ/地域タグ」** を主役にした小説カードとして並べる。
- **3段階のネタバレ配慮型・読書補助**:
  1. **冒頭「読む前の前提ガイド（ネタバレなし3行導入）」**: 時代背景・舞台・主人公の立ち位置だけを提示し、文脈迷子を防ぐ。
  2. **本文中「インライン用語ガイド（Popover）」**: 原文を一字一句改変せず、代名詞・難解語句（例：`{{cw_girl|燃える魔女がまだ少女}}`）をタップした時だけネイティブPopoverで正体・背景を表示する。また「用語ガイド ON/OFF」トグルで純粋な原文読書にも切り替えられる。
  3. **章末「読了後の真相・考察メモ（`<details>` 折りたたみ）」**: 読了後に初めて「実は〇〇（有名キャラ）の過去だった」という種明かしとゲーム内性能データを表示する。
- **時系列での章再構成**: 5部位に分かれた聖遺物や4段階の突破素材は、**物語の時系列順**に並べ替えて全5章（全4幕）の1本の短編小説として縦スクロールで通し読みさせる。
- **作品間のクロスリンク**: 『燃え盛る炎の魔女』⇄『終焉を嘆く詩』のように、表裏・前後関係にある別アイテムの物語を章末の `connected` カードで相互リンクする。

## 2. プロトタイプにおけるデータ収集方法とデータソースの事実関係

調査の結果、オープンソースの原神データリポジトリには**収録フィールドの明確な住み分け（欠落と補完関係）**があることが判明した。次のAIは無駄な再調査を行わず、以下の事実を前提とすること。

### リポジトリ別の収録内容比較

| データソース | 武器 (`weapons`) | 聖遺物 (`artifacts`) | 風の翼 (`windgliders`) | 素材・魔物・衣装等 (`materials`, `enemies`, `outfits`) | 書籍・七聖召喚・調度品 (`books`, `tcg_*`, `furnishing`) | 用途・特徴 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **`dvaJi/genshin-data`**<br>(npm: `genshin-data`) | ❌ 短文 `description` のみ（長文 `story` 欠落） | ❌ 各部位の短文 `description` のみ（長文 `story` 欠落） | ❌ 未収録 | ⭕ 素材・魔物（`monsters`）の `description` あり（衣装はキャラ内のみ） | ⭕ **書籍の巻構成・`storyId`**（本文は Yatta API で補完）、**七聖召喚カード（`desc`）**、**調度品（`description`）** を収録 | **書籍索引・七聖召喚フレーバー・調度品伝承の取得元** |
| **`theBowja/genshin-db`**<br>(npm: `genshin-db`) | ⭕ **`story` に長文ストーリー全文あり** | ⭕ **全5部位の `story` に長文ストーリー全文あり** | ⭕ **全19種の `story` に長文ストーリー全文あり** | ⭕ 突破素材・週ボス素材・突破宝石（`materials`）、魔物図鑑（`enemies`）、衣装（`outfits` ※`description`のみ）、地理・秘境・名刺を収録 | ❌ 書籍・調度品は未収録、七聖召喚は型定義のみで実データ未収録 | **聖遺物・武器・風の翼の長文 `story` および突破素材・週ボス素材・魔物図鑑・衣装のメインソース** |

### プロトタイプでのデータ取得手順
1. `theBowja/genshin-db` の `main` ブランチ（`src/data/Japanese/artifacts/*.json`, `weapons/*.json`, `materials/*.json`）から武器・聖遺物・突破素材のJSONを取得した。
2. 書籍『白夜国館蔵（日月前事 ほか全5巻）』は `dvaJi/genshin-data` の `src/data/japanese/books/the_byakuyakoku_collection.json` から巻構成と `storyId` を確認し、対応する日本語 Readable 本文データ（`Book332`〜`Book336`）を取得して統合した。
3. 聖遺物は `flower` / `plume` / `sands` / `goblet` / `circlet` の各オブジェクト内の `description`（エピグラフとして使用）と `story`（本文段落として使用）を抽出した。
4. 武器は `description`（エピグラフ）と `story`（本文段落）を抽出した。
5. 突破素材はレア度 ★2 → ★3 → ★4 → ★5 の4ファイルを1つの連作（第一幕〜第四幕）として結合した。

## 3. ストーリー再構成と人物名補完（アノテーション）の保管スキーマ

原文テキストには直接のキャラクター名が登場しないため、**別アイテム・週ボス素材・魔神任務とのクロスリファレンス（照合）**によって人物名を特定し、原文を壊さないインラインマークアップ形式で保管している。

### 3.1 人物名特定のロジック（クロスリファレンス根拠）
単一アイテムのテキストだけでは代名詞の正体は確定しない。以下の複数の公式ソースを突合して特定する。
- **パターンA（聖遺物 × 週ボス素材）**:
  - 例：聖遺物『燃え盛る炎の魔女』の「少女」＋ 聖遺物『蒼白の炎（無垢の花）』の「少女」 × 週ボス素材『溶滅の刻』『灰燼の心』＝ **ロザリン（ファデュイ執行官第八位『淑女』）**
- **パターンB（聖遺物 × 武器 × 他聖遺物）**:
  - 例：『燃え盛る炎の魔女（時の砂）』の「時計をくれた人」 × 武器『終焉を嘆く詩』の「悲しげな騎士（戦友エレンドリン・ローランドの名が登場）」 × 聖遺物『守護の心』 × 武器『西風剣』 ＝ **ルースタン**
- **パターンC（聖遺物内の要石章 × 各部位）**:
  - 例：『蒼白の炎』の理の冠『嗤笑の面』末尾にある唯一の实名「我が名は『道化』のピエロ」を起点に、各部位の「一人目の愚者」＝ **道化（ピエロ）**、勧誘された4人＝ **淑女・博士（ザンディク）・富者（パンタローネ）・散兵（スカラマシュ）** と特定。
- **パターンD（聖遺物 × 魔神任務・キャラストーリー）**:
  - 例：『華館夢醒形骸記』の「たたら砂」「傾奇者」「国崩」 × 魔神任務間章『伽藍に落ちて』＝ **放浪者（スカラマシュ）** と **雷電影（創造者）**・**八重神子（美しくて活気がある巫女）**。

### 3.2 データ保管スキーマ（`STORIES` オブジェクト構造）
プロトタイプ（`index.html` 内の `STORIES` 配列）では、1作品を以下のJSONスキーマで保管している。本番Webアプリでもこのスキーマを標準データモデル（`src/data/stories/*.json`）として採用すること。

```json
{
  "id": "crimson_witch",
  "title": "燃え盛る炎の魔女",
  "category": "聖遺物（連作短編）",
  "region": "モンド / スメール",
  "readingTime": "約4分",
  "hook": "愛する人を失った少女は、涙が枯れた日に自らの身体を「液体の炎」へと変えた——",
  "tags": ["ロザリン（淑女）", "500年前の災厄", "全5章・時系列順"],
  "preGuide": [
    "舞台：今から約500年前、テイワット全土を魔物の大群が襲った「漆黒の災厄」の時代。",
    "主人公：モンドからスメールの教令院へ留学していた、歌と炎の魔法を愛する少女。",
    "読みどころ：5つの部位にバラバラに書かれている記憶を、時系列順に並べています。"
  ],
  "overallTruth": "読了後にのみ開示する種明かし・考察テキスト",
  "gameEffect": "ゲーム内のセット効果・武器効果テキスト",
  "connected": [
    {
      "id": "elegy",
      "relation": "対になる裏視点の物語",
      "desc": "『終焉を嘆く詩』——彼女に水時計を贈り、モンドで帰りを待ちながら戦死した恋人ルースタンの最期"
    }
  ],
  "glossary": {
    "cw_lover": {
      "term": "時計をくれた人",
      "identity": "正体：西風騎士団の騎士「ルースタン」",
      "desc": "ロザリンの恋人であり、当時の西風騎士団を実質的に支えていた騎士。",
      "evidence": "聖遺物『守護の心（守護の座時計）』・武器『西風剣』『終焉を嘆く詩』"
    }
  },
  "chapters": [
    {
      "partLabel": "第一章（時の砂：魔女の破滅の時）",
      "heading": "静止した水時計",
      "epigraph": "部位や武器の短い description テキスト",
      "paragraphs": [
        "原文段落1",
        "原文段落2。インライン注釈は {{cw_lover|時計をくれた人}} の形式で埋め込む。"
      ],
      "chapterNote": "任意の1行補足メモ"
    }
  ]
}
```

### 3.3 インライン注釈記法 `{{term_id|表示文字列}}` の仕様
- 原文のテキストデータ内では `{{cw_lover|時計をくれた人}}` のように記述する。
- レンダラ（`formatParagraph` 関数）が正規表現 `/\{\{([a-z0-9_]+)\|([^}]+)\}\}/g` でパースし、HTMLの `<button type="button" class="glossary-term" popovertarget="pop-${storyId}-${termId}">` に変換する。
- ユーザーが「用語ガイド OFF」に切り替えた際は、CSSの `.reader-view[data-annotations="off"] .glossary-term` によって下線・背景色・クリック判定を無効化し、**DOMを再描画することなく純粋な原文テキストとして表示**する。

## 4. 本番Webアプリ化に向けた実装ステップと重要ポイント

次のAIエージェントは、以下の順序と完了条件（Completion Criteria）に従ってWebアプリ化を進めること。

### Step 1: 静的サイトジェネレータ（SSG）または軽量フロントエンド基盤への移行
- **方針**: 実行時サーバーやデータベース、ランタイムAI API呼び出しは一切持たず、**完全な静的サイト（Astro または Vite + TypeScript）**として構築する。これによりインフラ維持費ゼロ・高速表示を担保する。
- **完了条件**:
  - `index.html` 内の6作品データが `src/content/stories/*.json`（またはディレクトリ分割JSON）として外部ファイル化され、型検証（Zod等）を通過すること。
  - プロトタイプで実装した原神「図鑑」風の星空・天球ステージ（ホログラム線画アイコン、天文盤、読書時の背景減光）、スクロール連動ヘッダー、ネイティブ `popover` 用語解説、`<details>` 真相メモがすべて維持されていること。

### Step 2: ビルド時「AIクロスリファレンス＆注釈生成パイプライン」の構築
数多くの武器・聖遺物を手作業で注釈付けするのはスケールしないため、**開発ローカル／ビルド時の事前バッチスクリプト**として以下を構築する。
1. **知識インデックスの作成**:
   - `theBowja/genshin-db` の全日本語データ（`characters`, `artifacts`, `weapons`, `materials`, `windgliders`, `outfits`）を1つのローカル検索インデックスに束ねる。
2. **バッチ変換スクリプト（`scripts/enrich-story.ts`）**:
   - 対象の武器・聖遺物の生データ（`story`）を入力とし、関連キーワードでローカル検索インデックスから関連キャラ・ボス素材・他装備のテキストを抽出する。
   - LLM（Gemini API等、開発時のみ実行）に対し、抽出した公式テキスト根拠とともにプロンプトを渡し、上記 `3.2` のJSONスキーマ（`hook`, `preGuide`, 時系列順の `chapters`, `{{term_id|...}}` タグ付きの原文, `glossary`, `overallTruth`, `connected`）を出力させる。
   - **厳守ルール**: 原文（`paragraphs`）の文字・改行・句読点は `{{term_id|...}}` で囲む以外、**1文字たりとも改変・要約しない**ようバリデーション（タグ除去後の文字列完全一致チェック）をスクリプトに組み込むこと。
- **完了条件**:
  - タグ除去後の `paragraphs` 結合文字列が、`genshin-db` の元の `story` 文字列と100%一致する自動テストが通ること。

### Step 3: 書籍アイテム（`books`）本文データの統合
- **課題**: `dvaJi/genshin-data` の `books/*.json` には `storyId`（Readable ID）しかなく、`theBowja/genshin-db` にも書籍本文は含まれていない。
- **解決策**: 書籍アイテム（『白夜国館蔵』『酔っぱらいの逸話』『イノシシプリンセス』等）を追加する際は、`storyId` に対応する日本語 Readable テキストデータ（Project Amber API や Yatta API 等の `readable` エンドポイント、またはローカル抽出した Readable テキスト辞書）を `dvaJi/genshin-data` の `volumes[].storyId` に結合する取得スクリプトを作成する。
- **完了条件**:
  - 書籍シリーズの複数巻（`volumes`）が、聖遺物の全5章と同じく `chapters` 配列に変換され、同じリーダーUIでシームレスに読めること。

### Step 4: 検索・フィルタ・読了状態のローカル保存
- **機能追加**:
  - キャラクター名・地域・時代（「500年前（厄災）」「魔神戦争」「旧貴族時代」等）での横断フィルタリング。
  - `localStorage` を用いた「読了チェックマーク」「しおり（途中まで読んだスクロール位置の復元）」。
- **知的財産権（IP）ガイドラインへの配慮**:
  - フッター等に HoYoverse の二次創作・非公式ファンサイトガイドラインに基づく権利表記（「本サイトはHoYoverseの公式サービスではありません。ゲーム内テキストの著作権はCOGNOSPHERE PTE. LTD.に帰属します」等）を明記し、広告や課金機能を持たない非営利・閲覧支援構成を維持する。
