# 0005: GA4 直接計測・HashRouter 手動 page_view・サイト内オプトアウト方式

[ADR-0001](0001-static-site-and-localstorage-persistence.md) で定めた完全静的サイト構成を維持したまま、作品別の閲覧動向・横断検索需要（ヒット0件語句含む）・読書完了率・導線別回遊を把握するため、Google Analytics 4（GA4 / `gtag.js`）をクライアントサイドへ直接組み込む。

## Considered Options

- **GA4（`gtag.js`）直接導入 ＋ Vite 環境変数注入 ＋ フッター告知＆サイト内オプトアウト（採用）**:
  - タグ管理コンテナ（GTM）を挟まずアプリ側でイベント発火とオプトアウト停止を一元制御できるため、二重計測リスクと運用複雑性を抑えられる。
  - `send_page_view: false` で自動計測を停止し、`HashRouter` 遷移と非同期 JSON 取得（`document.title` 確定）に合わせて仮想パス（`/`・`/story/<id>`）を手動送信することで、検索クエリ `?q=` 更新による過剰計測を防げる。
  - 同意バナーによる初回読書導線の阻害を避けつつ、フッター常設の「アクセス解析について」ダイアログで収集範囲の明記と `localStorage` ＋ `window["ga-disable-<ID>"]` による即時オプトアウトを提供する。
- **Google タグマネージャー（GTM）経由の配信**: 複数外部タグを非エンジニアが付け替える用途には適するが、GA4 単体構成では GTM 側コンテナ定義・オプトアウト連動設定の二重管理となりオーバーヘッドが大きい。
- **初回全画面／下部バナーによる Consent Mode v2 オプトイン必須化**: 厳格だがライトユーザーの初回読書体験を阻害するため、個人情報非収集＋サイト内オプトアウト切替方式を採用した。
- **独自バックエンドでのアクセスログ収集**: ADR-0001 の完全静的構成（ゼロ・バックエンド）に反するため不採用。

## Consequences

- `VITE_GA_MEASUREMENT_ID` が設定され、かつ「本番ビルド（`PROD`）かつローカルホスト以外」または明示的デバッグ指定（`VITE_GA_DEBUG=true`）の時のみ `gtag.js` を動的読み込みする。ローカル開発・Vitest・Playwright E2E では外部通信を一切発生させない。
- 横断検索語句（`search_term`）は 800ms デバウンス後にメールアドレス・電話番号様数値列の簡易マスクと 100 文字制限を適用して送信する。
- GA4 管理画面側では、手動 `page_view` との重複を防ぐため拡張計測機能の「ページ変更に基づくイベント」を無効化し、イベントパラメータ用のカスタムディメンション／指標を登録する（[`docs/guides/GOOGLE_ANALYTICS_SETUP.md`](../guides/GOOGLE_ANALYTICS_SETUP.md) 参照）。
