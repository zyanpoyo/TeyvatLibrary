# 読書コース（フェア棚）編入・編集ガイド

新しいストーリーを追加した際や既存コースを見直す際に、[`data/shared/courses.json`](../../../../data/shared/courses.json) を判断・編集するための基準。データ形式の正本は [`data/schemas/courses.schema.json`](../../../../data/schemas/courses.schema.json) を参照。

---

## 1. 編入 vs 新設の基準

- **既存コースへの追記**: 既存の入門・キャラ別・地域／歴史別コースのテーマや時系列に自然に接続する作品は、適切な読書順の位置へ `steps` を差し込む（同じ作品を複数コースへ所属させてよい）。
- **新コースの立ち上げ**: 関連作品が **3 篇以上** 揃った時点、または特定のキャラ・事件・時代を一本道で追えるまとまりができた時点で新設を検討する。

---

## 2. 看板と中身の一貫性・2 段構え

- **タイトルと収録作のベクトルを一致させる**: コース名・副題が約束する主題（例：「世界の核心」「〇〇の軌跡」）から外れる作品を、知名度や短さだけで混ぜない。
- **入門版と完全版の棲み分け**: 創世記など収録数や読了時間が重い領域は、「まずは要点を掴む入門版（厳選 3〜4 篇）」と「周辺神話まで網羅する完全版（6〜7 篇以上）」に分けて案内する。

---

## 3. 書架フェア棚・代表 3 枠（`featured: true`）の原則

書架トップのフェア棚は、初見読者の入り口として以下を基準に 3 枠を維持する。

1. **種別バランス**: `beginner`・`character`・`arc` から原則 1 枠ずつ選出する。
2. **代表枠間の重複ゼロ**: 代表 3 コース同士で同じ `storyId` が重複しないように組み、並び立つ 3 枚がすべて別の物語体験を提示する状態にする。

---

## 4. 日本語読者向け表記と順路ガイド（`note`）

- **馴染みのないカタカナ翻訳語を使わない**: 種別やバッジ、紹介文に「アーク」「ウォームアップ」などの直訳カタカナ語を避け、「地域・歴史別」「〇〇編」「連作編」「最初の扉」など文庫として自然な和語・漢字を選ぶ。
- **全フィールドが公式コーパス検査対象**: `badge`・`title`・`subtitle`・`hook`・`seo`・`steps[].note` も `npm run validate` でカタカナ語・NG 表記をチェックされる。一般カタカナ語を増やさず和語・漢字で記述する。
- **順路ガイド（`steps[].note`）の役割**: 真相や結末を明かさず、**「なぜこの順番のここで読むのか」**（視点の対比・時代順の位置づけ・読む長さ）を 1 行で伝える。

---

## 5. コース変更時の連動チェックリスト

コースの収録数・タイトル・対象作品を更新したら、次を合わせて確認する。

- [ ] `badge` 内の件数表記（例：`厳選4選`）が実際の `steps.length` と一致しているか
- [ ] [`doc-sync`](../../doc-sync/SKILL.md) 対象ドキュメント（特に [`phase3_curation_courses.md`](../../../../docs/handoff/retention/phase3_curation_courses.md) や [`DATA_ARCHITECTURE.md`](../../../../docs/architecture/DATA_ARCHITECTURE.md) の例示）に古い件数・例が残っていないか
- [ ] [`tests/e2e/ssg-prerender.spec.js`](../../../../tests/e2e/ssg-prerender.spec.js) など実データを読む E2E テストが通るか
- [ ] `npm run build` 後、`build/client/og/course/<id>.png`（確認コマンド：`npm run build:og -- --only course/<id> --force`）に文字欠けや改行崩れがないか目視する
