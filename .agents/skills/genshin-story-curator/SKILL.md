# Genshin Story Curator（原神ストーリー抽出・構造化・関連付けスキル）

原神のゲーム内テキスト（書籍・聖遺物・武器・突破素材・風の翼）から日本語の公式長文データを抽出し、**原文を一字一句改変せずに**ライトユーザー向けの「前提ガイド・インライン用語Popover・真相メモ・作品間リンク」付き小説データへ変換する手順。

---

## Step 1: データソースの選定と生データ抽出

対象のアイテム種別に応じて、長文ストーリー（Readable本文）が収録されている正しいデータソースを選択する。

| 対象種別 | 取得元データソース | 抽出対象フィールド | 注意点 |
| :--- | :--- | :--- | :--- |
| **聖遺物** (`artifacts`) | `theBowja/genshin-db`<br>(`src/data/Japanese/artifacts/<id>.json`) | `flower`, `plume`, `sands`, `goblet`, `circlet` 内の `description`（エピグラフ）と `story`（長文本文） | `dvaJi/genshin-data` には `story` が存在しないため使用しない |
| **武器** (`weapons`) | `theBowja/genshin-db`<br>(`src/data/Japanese/weapons/<id>.json`) | `description`（エピグラフ）と `story`（長文本文） | `dvaJi/genshin-data` には `story` が存在しないため使用しない |
| **突破素材** (`materials`) | `theBowja/genshin-db` または `dvaJi/genshin-data` | ★2・★3・★4・★5 の4ファイルの `description` | 冒頭の定型文「武器に突破の力を付与する材料。\n」は除去し、物語本文のみを抽出する |
| **書籍** (`books`) | 1. `dvaJi/genshin-data` (`src/data/japanese/books/<id>.json`)<br>2. Yatta Readable API (`https://gi.yatta.moe/api/v2/jp/book/<_id>` 及び `.../readable/Book<storyId>`) | 1. 書籍名・巻構成・` _id`<br>2. 各巻の `storyId` に対応する日本語 Readable 本文文字列 | `genshin-data` 単体では `storyId` のみで本文が欠落しているため、必ず Readable API で本文を取得する |

### 実行手順
1. **GitHub通信の事前承認確認**: `theBowja/genshin-db` や `dvaJi/genshin-data` へ新規に通信する場合は、ユーザーのグローバルルールに従い、事前に「目的・対象・内容」を明示して承認を得る（同一セッション内で承認済みの場合はそのまま実行可）。
2. [fetch-genshin-lore.ps1](./scripts/fetch-genshin-lore.ps1) を使用して生JSONを取得する。このスクリプトは取得した公式原文内のカタカナ語を自動で `official-corpus.json` へ学習・マージする。

- **完了条件**: 対象作品の日本語原文テキスト（全部位・全段階・全巻）が欠落なくローカルに取得できていること。

---

## Step 2: 物語の時系列再構成（章立て）

ゲーム内のアイテム格納順は物語の時系列と一致しないことが多い。ライトユーザーが小説として自然に読めるよう、`chapters` 配列の順序を再構成する。

1. **聖遺物（全5章）**:
   - デフォルトの部位順（花→羽→砂→杯→冠）のまま並べず、5部位のテキストを読んで**「主人公の過去（発端）→ 転機（災厄・喪失）→ 現在の姿（結末）」の時系列順**、またはオムニバス形式として最も理解しやすい順序に並べ替える。
   - 例：『燃え盛る炎の魔女』は「時の砂（留学と恋人の死）→ 生の花（魔女誕生）→ 空の杯（液体の炎）→ 理の冠（焦げた顔を隠す帽子）→ 死の羽（孤独な旅路）」の順に並べる。
   - 各章の `partLabel` に元の部位名（例：`第一章（時の砂：魔女の破滅の時）`）を明記し、原典との対応を保持する。
2. **武器突破素材（全4幕）**:
   - レア度順（★2 第一幕 → ★3 第二幕 → ★4 第三幕 → ★5 第四幕）に4つの章として連結する。
3. **書籍（複数巻シリーズ）**:
   - シリーズの中で最も核心となる巻（例：『白夜国館蔵』における第2巻『日月前事』）が長大な場合は、見出しごとに前半・後半の部に分割し、読了負担を下げる。

- **完了条件**: 各章に `partLabel`（原典部位・巻名）、`heading`（内容を端的に表す小説風章タイトル）、`epigraph`（アイテムの短文 `description`）、`paragraphs`（段落配列）が設定されていること。

## Step 3: 伏せられた人物名・用語のクロスリファレンス特定と注釈埋め込み

原神のテキストで伏せられている代名詞（「少女」「彼」「一人目の愚者」「創造者」など）や難解な歴史用語を、他アイテムのテキストと照合して特定し、3段階の読書補助に振り分ける。詳細な照合パターンとJSONスキーマは [cross-reference-patterns.md](./references/cross-reference-patterns.md) を参照すること。

1. **冒頭 `preGuide`（読む前の前提ガイド・3行）**:
   - ネタバレ（結末の真相）は書かず、「① 時代・舞台」「② 主人公の立ち位置」「③ 章構成や読みどころ」の3点のみを簡潔に記述する。
2. **本文中 `{{term_id|表示文字列}}` と `glossary`（インライン用語解説）**:
   - 原文中の代名詞や重要語句を `{{term_id|原文の文字列}}` で囲む。
   - **厳守ルール**: `|` の右側の表示文字列は、**原文の文字・送り仮名・表記を一字一句そのまま維持**すること（原文を書き換えたり、括弧書きを足したりしてはならない）。
   - 対応する `glossary[term_id]` に以下の4フィールドを必ず設定する：
     - `term`: 見出し語
     - `identity`: 必ず **`正体：` / `真名：` / `鳴神名：` / `解説：` / `有力説：`** のいずれかのプレフィックスで始めること（公式未明言の考察は必ず `有力説：` とし、断定しない）。
     - `desc`: 2〜3文の背景解説
     - `evidence`: その人物・用語特定の裏付けとなる**公式テキスト名・アイテム名・任務名**（例：`週ボス育成素材『溶滅の刻』・聖遺物『燃え盛る炎の魔女』`）
3. **章末 `overallTruth`（読了後の真相・考察メモ）**:
   - 読了後に `<details>` を開いた人向けに、「実は〇〇（キャラ名）の過去であり、どのボス素材・魔神任務・別装備とどう繋がっているか」の種明かしを記述する。

- **完了条件**: `paragraphs` から `{{term_id|...}}` のタグ記法を除去した文字列が、取得した元の `story` テキストと1文字の狂いもなく一致していること。

## Step 4: 作品間の関連付け（双方向 `connected` リンク）

単一の装備・書籍で完結させず、表裏・前後関係にある他作品と双方向にリンクを張る。

1. **関連作品の特定**:
   - **表裏視点**: 同じ出来事を別人物の視点から描く作品（例：『燃え盛る炎の魔女』ロザリン視点 ⇄ 『終焉を嘆く詩』ルースタン視点）。
   - **時系列の前後**: 前日譚・後日譚にあたる作品（例：『燃え盛る炎の魔女』→『蒼白の炎（無垢の花）』、または『白夜国館蔵（日月前事）』→『誓いの明瞳』→『遠海夷地の珊瑚枝』）。
   - **同時代・同地域の群像劇**: 同じ時代の別英雄（例：『狼の末路』北風の騎士 ⇄ 『獅牙戦士の叙事詩』ヴァネッサ）。
2. **双方向更新**:
   - 新規追加した作品の `connected` 配列に既存作品へのリンクを追加するだけでなく、**リンク先の既存作品の `connected` 配列にも新規作品への逆リンクを追加**する。
3. **図鑑カウントとカテゴリーの更新**:
   - ヘッダーの総件数（`#total-count-label`）および図鑑ステージの各ホログラムアイコンの件数表記（`.holo-count`）を実際の収録数に合わせて更新する。
4. **追加日（`addedAt`）の付与（任意）**:
   - 新規ストーリーを追加する場合は、トップレベルに `"addedAt": "YYYY-MM-DD"` を設定すると、書架の「新着順」並び替えおよび追加から14日間（未読時）の `NEW` バッジ対象として扱われる。

- **完了条件**: 新規作品と関連作品の双方向でクリック遷移が可能であり、一覧画面のカテゴリー絞り込み件数と一致していること。

## Step 5: 公式コーパス自動照合＆類似語サジェスト検証（必須）

データ追加・編集後は、必ずガードレール検証スクリプトを実行して固有名詞の表記揺れ・未検証カタカナ・出典欠落を検査する。

```powershell
pwsh -File .agents/skills/genshin-story-curator/scripts/validate-stories.ps1
```

ゲームのバージョンアップ時に公式コーパスを最新化したい場合は、以下を実行する（`official-corpus.json` が未存在時は検証スクリプトが自動で同期する）：

```powershell
pwsh -File .agents/skills/genshin-story-curator/scripts/sync-official-corpus.ps1
```

### エラー検出時の対処ルール
1. **`[NG固有名詞検出]`**: [official-entities.json](./resources/official-entities.json) の `ngVariants` に登録された誤記・旧翻訳（例：`ロストム`→`ルースタン`、`エイカンデル`→`エレンドリン`、`セレスティア`→`天空の島`）が含まれているため、指定された公式表記へ修正する。
2. **`[公式コーパス未登録カタカナ]`**: `official-corpus.json`（`genshin-data`＋`genshin-db` 最新版＋取得済み原文から自動生成）に1度も登場しないカタカナ語が含まれている。
   - **エラーメッセージに表示される「もしかして公式表記: …」の類似語サジェスト**を確認し、誤記（例：`バネッサ`→`ヴァネッサ`、`ドットレ`→`ドットーレ`）であれば即座に公式表記へ修正する。
   - 魔神任務の会話セリフや公式PV・公式漫画のみに登場する固有名詞である場合は、根拠を確認の上で [official-entities.json](./resources/official-entities.json) の `officialMediaTerms`（または一般解説語であれば `allowedCommonKatakana`）に最小限追加する。
3. **`[出典根拠欠落]` / `[確度区分欠落]`**: 該当する `glossary` エントリに `evidence` と `identity` の確度プレフィックスを設定する。

- **完了条件**: `validate-stories.ps1` が終了コード `0`（`✅ 検証成功`）でパスすること。
